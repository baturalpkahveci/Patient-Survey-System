# Hasta Memnuniyet Anketi Sistemi

ASP.NET Core MVC, Razor Views, EF Core ve PostgreSQL kullanan katmanlı hasta memnuniyet anketi uygulaması.

## Structure

- `src/PatientSurvey.Domain`: entities and enums only.
- `src/PatientSurvey.Application`: DTOs, interfaces, and business workflows.
- `src/PatientSurvey.Infrastructure`: EF Core `AppDbContext`, configurations, migrations, repositories, clock, password hashing, patient identity hashing, and development delivery senders.
- `src/PatientSurvey.WebUI`: MVC controllers, Razor views, authentication, authorization, session verification state, and DI composition.
- `tests/PatientSurvey.UnitTests`: isolated Application tests with fake repositories.
- `tests/PatientSurvey.IntegrationTests`: EF model and MVC authorization integration checks.

## Current Domain Flow

Patient-specific links are modeled separately from survey definitions:

```text
Patient
  -> PatientVisit
  -> SurveyInvitation
  -> SurveyAccessToken
  -> SurveyResponse
  -> Answer
```

`Survey` is the survey definition. `SurveyInvitation` is one patient-specific invitation for one `PatientVisit`. Every newly generated survey link must be tied to a patient, visit, invitation, and unique access token.

General survey means `Survey.DoctorId = null` and `Survey.DepartmentId = null`. It is not anonymous. Targeted survey means both doctor and department are set, and the generated `PatientVisit` uses the same scope.

## Roles

- `Admin`: survey, question, department, user, result, report, and patient-specific invitation workflows.
- `Manager`: result/report/link listing only. Patientless link creation is disabled.
- `Doctor`: only the Doctor area. Can create a survey/invitation, but cannot view patients, patient history, results, reports, users, roles, or question administration.

Doctor-facing DTOs and Razor models must not return patient PII after invitation creation. Success screens show only link, delivery status, and a pseudonymous patient reference.

## Privacy And Security

T.C. Kimlik Numarası is not stored in plaintext. `Patient.TcIdentityLookupHash` stores a deterministic HMAC lookup value generated by `IPatientIdentityProtector`.

Do not log raw TC, TC hashes, phone numbers, email addresses, passwords, password hashes, full tokens, HMAC keys, or connection string passwords.

Patient survey access uses a two-step flow:

1. Patient opens `/Survey/{token}`.
2. Server validates token and shows only TC verification plus the centralized KVKK notice.
3. TC is matched only against the patient attached to that specific invitation.
4. Verification state is stored server-side in session as invitation id and notice version only, never raw TC.
5. Survey questions can be shown and submitted only after verification.
6. `SurveyResponse`, `Answer`, `SurveyConsent`, and `SurveyAccessToken.UsedAtUtc` are saved atomically in one transaction.

Production kullanımı öncesinde KVKK Aydınlatma Metni, veri işleme hukuki sebebi, saklama süresi ve gerekiyorsa açık rıza süreçleri kurumun hukuk/KVKK sorumlusu tarafından doğrulanmalıdır.

## Configuration

The application reads PostgreSQL from `ConnectionStrings:DefaultConnection`.

Patient identity lookup hashing requires:

```bash
PATIENT_IDENTITY_KEY=replace-with-at-least-32-random-characters
```

For Docker Compose, create a local `.env` from `.env.example` and set real local secrets. Do not commit `.env`.

SMS and e-posta delivery are represented by `ISmsSender` and `IEmailSender`. The current Infrastructure implementations are development/no-op senders that mark delivery as `NotConfigured`; links are still created and shown.

## Database

Create a migration:

```bash
dotnet ef migrations add MigrationName --project src/PatientSurvey.Infrastructure --startup-project src/PatientSurvey.WebUI --output-dir Persistence/Migrations
```

Apply migrations:

```bash
dotnet ef database update --project src/PatientSurvey.Infrastructure --startup-project src/PatientSurvey.WebUI
```

Reset a local development database by removing the Docker volume:

```bash
docker compose down -v
```

## Run

```bash
dotnet restore PatientSurvey.slnx
dotnet build PatientSurvey.slnx
dotnet test PatientSurvey.slnx
```

Run with Docker:

```bash
docker compose up --build
```

The WebUI listens on `http://localhost:8080` and connects to PostgreSQL through the Compose service name `db`.
